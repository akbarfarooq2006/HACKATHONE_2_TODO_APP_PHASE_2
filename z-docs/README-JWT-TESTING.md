## 🔑 Key Concepts

### Two-Token Architecture

**Session Tokens (Frontend)**
- **What**: `ZYxRoYkgU8tlrAEkc5bM5iDTfWKBVT3L...`
- **Where**: Browser cookies (automatic)
- **Purpose**: Frontend session management
- **Verification**: Database lookup
- **Lifetime**: 7 days

**JWT Tokens (Backend API)**
- **What**: `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...`
- **Where**: Generated on-demand (not stored)
- **Purpose**: Backend API authentication
- **Verification**: Cryptographic (stateless)
- **Lifetime**: Generated fresh each time

### Why Two Different Tokens?

**Session Tokens:**
- Optimized for browser-based authentication
- Can be revoked by deleting from database
- Supports session updates
- Better Auth handles complexity

**JWT Tokens:**
- Optimized for stateless API authentication
- No database lookup (faster)
- Standard format (works with any JWT library)
- Can be used by external services

## 💻 Code Examples

### Get JWT Token in Component

```typescript
import { getJWTToken } from '@/lib/auth-client';
import { useSession } from '@/lib/auth-client';

export default function MyComponent() {
  const { data: session } = useSession();
  
  const handleAPICall = async () => {
    // Get JWT token
    const jwt = await getJWTToken();
    if (!jwt) return;
    
    // Call backend API
    const response = await fetch(
      `http://localhost:8000/api/v1/users/${session.user.id}/me`,
      { headers: { 'Authorization': `Bearer ${jwt}` } }
    );
    
    const data = await response.json();
    console.log(data);
  };
  
  return <button onClick={handleAPICall}>Call API</button>;
}
```

### Test in Browser Console

```javascript
// Get JWT token
const res = await fetch('/api/auth/token');
const { token } = await res.json();
console.log('JWT:', token);

// Decode payload
const payload = JSON.parse(atob(token.split('.')[1]));
console.log('User ID:', payload.sub);

// Test backend
const api = await fetch(`http://localhost:8000/api/v1/users/${payload.sub}/me`, {
  headers: { 'Authorization': `Bearer ${token}` }
});
console.log('Response:', await api.json());
```

## 🐛 Troubleshooting

### Issue: "Failed to get JWT token"

**Symptoms:**
- Test page shows error
- Console shows "Failed to get JWT token"

**Solutions:**
1. Verify you're signed in (check /dashboard)
2. Clear browser cache (F12 → Application → Clear site data)
3. Sign out and sign in again
4. Check frontend terminal for errors

### Issue: Backend returns 401 Unauthorized

**Symptoms:**
- API call fails with 401
- Error: "Could not validate credentials"

**Possible Causes:**
1. BETTER_AUTH_SECRET mismatch
2. Backend not running
3. Token expired or invalid

**Solutions:**
```bash
# Check secrets match
cat frontend/.env.local | grep BETTER_AUTH_SECRET
cat backend/.env | grep BETTER_AUTH_SECRET

# Restart both servers if they don't match
```

### Issue: Backend returns 403 Forbidden

**Symptoms:**
- API call fails with 403
- Error: "User ID in path does not match token user ID"

**This is CORRECT behavior!**
- ✅ JWT token is valid
- ✅ Path-based security is working
- ❌ user_id in URL doesn't match token's `sub` claim

**Solution:**
- Use correct user_id from token's `sub` claim
- Test page handles this automatically

### Issue: Token doesn't start with "eyJ"

**Symptoms:**
- Token looks like: `ZYxRoYkgU8tlrAEkc5bM5iDTfWKBVT3L...`
- Not in JWT format

**This means:**
- You're looking at the **session token** (in cookies)
- This is CORRECT for session management
- JWT tokens are generated separately

**Solution:**
- Go to http://localhost:3000/test-jwt
- Click "Get JWT Token"
- That will show the JWT token in `eyJ...` format
